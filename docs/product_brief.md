# Watchlist Pulse Product Brief

## 结论

优先级 A。它比一次性研究报告更容易形成持续使用，也更自然消耗 QVeris credits。

## 用户

- 核心用户：每天关注 5-50 只美股的个人投资者、研究者、创作者。
- 次级用户：小团队研究员、newsletter 作者、社群主。
- 开发者用户：想把自选股提醒接入 Slack、Discord、Telegram、飞书、邮件或内部工具的人。

## 用户问题

用户不是缺信息，而是每天不知道自己的 watchlist 里哪些变化值得看。手动刷价格、新闻、filing、财报日历和评级变化太碎，容易漏掉重要变化，也容易被噪音带偏。

## 产品假设

- [assumption] 用户愿意每天早上读一份 1-3 分钟的个性化简报。
- [assumption] watchlist 是比一次性 ticker 查询更强的留存入口。
- [assumption] 免费 5 只能让用户感知价值，50 只是付费升级的自然理由。

## 核心价值

每天回答 3 个问题：

1. 我的 watchlist 里发生了什么？
2. 哪些变化真的值得关注？
3. 我需要进一步验证什么，而不是直接下结论？

## 成功指标

- 激活：新用户 24 小时内创建 watchlist 的比例 >= 60%。
- 留存：创建 watchlist 用户的 D7 留存 >= 35%。
- 习惯：日报 7 日内平均打开天数 >= 3 天。
- 付费：免费用户触达 5 只上限后的升级点击率 >= 10%。
- 成本：单用户单日报平均 LLM + 数据成本低于目标 ARPU 的 10%。

## 功能优先级

| 优先级 | 功能 | 说明 |
|---|---|---|
| P0 | Watchlist 管理 | 添加、删除、排序 ticker，限制免费/付费数量 |
| P0 | 日报生成 | 每个交易日盘前生成 |
| P0 | 邮件推送 | 最少渠道，最快验证习惯 |
| P0 | 异动解释 | 价格/成交量 + 新闻/filing/财报上下文 |
| P1 | 周报生成 | 每周总结变化和下周事件 |
| P1 | 用户 thesis | 用户为每只股票写一句关注理由 |
| P1 | API/Webhook | 给开发者和团队接 Slack/Discord/Telegram/飞书 |
| P2 | 个性化偏好 | 用户选择偏成长、财报、事件、风险、技术面 |

## 风险

- 噪音太多：需要每份报告只突出最重要的 3-7 条。
- 成本失控：先批量取数据，LLM 输入只喂结构化摘要。
- 合规风险：避免 "buy/sell/target price" 口吻，使用 "值得关注/需要验证"。
- 留存不足：日报必须稳定、准时、短，而不是像长报告。
